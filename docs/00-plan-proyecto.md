# Plan del proyecto

Cada fase deja un entregable que luego se aprovecha en la memoria del TFG. No se pasa a la siguiente hasta revisar el entregable de la anterior.

| Fase | Qué hacemos | Entregable | Apartado de la memoria |
|---|---|---|---|
| 1. Análisis | Definir el problema, los usuarios y los requisitos | `docs/01-analisis.md` | Introducción, objetivos, análisis |
| 2. Diseño | Modelo de datos, casos de uso, arquitectura, contrato de la API y bocetos de pantallas | Diagramas E/R, de casos de uso y de clases, y wireframes | Diseño |
| 3. Preparación | Docker, proyectos base, ramas de Git y flujo de trabajo | Entorno que arranca con un solo comando | Tecnologías y entorno |
| 4. Backend | Base de datos, API REST, autenticación y pruebas | API funcionando y documentada con Swagger | Desarrollo |
| 5. App Android | Pantallas, conexión con la API y escáner | App funcionando contra la API | Desarrollo |
| 6. Pruebas | Pruebas unitarias, de integración y manuales | Plan de pruebas con resultados | Pruebas |
| 7. Despliegue | Publicar la API en un servidor y generar el APK firmado | Versión instalable | Despliegue |
| 8. Cierre | Manual de usuario, memoria y ensayo de la defensa | Memoria y presentación | Conclusiones y anexos |

## Reglas de trabajo

- **Paso a paso:** se explica cada decisión y tú escribes parte del código, para poder defenderlo ante el tribunal.
- **Git desde el principio:** una rama por funcionalidad y commits pequeños. El historial también demuestra tu proceso de trabajo.
- **Decisiones anotadas:** cada decisión importante se escribe con su motivo. Es lo que el tribunal suele preguntar.
- **Primero el mínimo viable:** los extras solo se añaden cuando lo imprescindible ya funciona.

## Antes de presentar el TFG real

Confirma con tu tutor o tutora el índice exigido, la extensión y las fechas de tu centro. Los apartados de esta tabla son orientativos, porque cada centro tiene sus normas.
